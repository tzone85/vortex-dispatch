# Always-On Agent Status Surfacing — Design Spec

**Date:** 2026-06-16
**Status:** Draft

## Problem

After `vxd req "..."` the user has to type `vxd status <req-id>` (and remember the ID) to see what the agents are doing. Foreground runs do print an inline stream, but the moment the user backgrounds (`--background`) or opens a new shell, the work becomes invisible. The CLI command surface trades discoverability for keystrokes the user does not want to spend.

## Goal

Make agent work continuously visible — automatically in a browser for visual users, and in the terminal stream / `vxd watch` for terminal users — without anyone having to type `vxd status <id>` again.

## Non-goals

- Notifications (OS push, email, Slack). Out of scope for this iteration.
- Replacing the existing TUI dashboard. `vxd dashboard` (Bubbletea) keeps its current behaviour.
- Multi-user remote dashboards. Local-host only; auth via existing bearer-token middleware.

## Decisions (from brainstorm)

| Decision | Choice |
|---|---|
| Trigger | Auto-spawn on every `vxd req` |
| Lifecycle | Long-lived background daemon, reused across `vxd req` calls |
| Terminal default | Keep inline stream; add banner URL; add `vxd watch [req-id]` for compact tail |
| Headless | Detect SSH / no DISPLAY / non-TTY / `auto_open=false`, fall back to URL-only |

## Architecture

```
vxd req "X"
  ├─ runDispatchPreflight  (existing)
  ├─ plan(...)             (existing)
  ├─ dashstart.Ensure(cfg) ──── reuse running daemon | spawn detached
  ├─ banner: Dashboard: http://localhost:PORT/?req=<id>&bootstrap=<nonce>
  ├─ if !IsHeadless: open browser
  └─ runResume(reqID)      (existing inline stream)

vxd watch [req-id]                  ← new
  └─ EventStore.Tail → one-line-per-event renderer to stdout

vxd dashboard status|stop           ← new subcommands of existing `vxd dashboard`
  └─ pidfile + healthz; SIGTERM
```

The daemon is just `vxd dashboard --web` with two new flags (`--pidfile`, `--bootstrap-file`) that let other CLI processes find and reuse it. No new long-running service binary.

## Components

### `internal/dashstart` (new package)

Small package of pure functions so spawn/probe/headless logic can be unit-tested without forking real processes or reading real env vars in test code.

- `Spawn(self, cfg) *exec.Cmd` — builds detached `exec.Cmd` for `vxd dashboard --web --port=… --pidfile=… --bootstrap-file=…`. Reuses platform-specific `applyDaemonDetach` already present in `internal/cli/req_unix.go` / `req_windows.go` — extracted to this package.
- `IsAlive(pidfile string, httpClient HTTPDoer) (port int, alive bool, err error)` — reads pidfile, checks `kill -0` (Unix) / `OpenProcess` (Windows), GETs `/healthz`. `HTTPDoer` is an interface so tests use a stub.
- `IsHeadless(env Environ, isTTY func() bool, cfgAutoOpen bool) (bool, string)` — pure check returning whether to skip browser-open plus reason for logging. `Environ` is an interface (`Getenv(string) string`) so tests don't poke real env.
- `Ensure(ctx, cfg) (DashboardHandle, error)` — orchestrator. Probe → reuse | spawn + healthz-wait. Times out at 3 s, polls 100 ms. Returns `DashboardHandle{Port, BootstrapNonce, URL}`. Never blocks `vxd req` longer than the timeout; on failure returns an error the caller logs but proceeds past.

### Edits to `internal/web/server.go`

- New flags wired by `internal/cli/dashboard.go`: `--pidfile string`, `--bootstrap-file string`.
- On `Server.Start`: after `Listen()` succeeds, atomically write pid to pidfile (write to `pidfile.tmp` then rename) with mode `0o600`. On shutdown: best-effort `os.Remove(pidfile)`.
- On `Server.Start`: write the initial bootstrap nonce (already generated by existing `auth.go`) to `--bootstrap-file` path with mode `0o600`. Nonce is single-use; the daemon rotates it after the first consumption. When a later `vxd req` needs a new nonce, the daemon exposes `POST /internal/bootstrap` (loopback-only check, no token required from `127.0.0.1`) which generates and returns a fresh nonce. This keeps every browser tab opened by `vxd req` working without leaking nonces to the filesystem long-term.

### Edits to `internal/cli/req.go`

Between `Plan(...)` completing and `runResume(...)` being called:

1. Skip if `dryRun` (no real work to watch).
2. Call `dashstart.Ensure(ctx, cfg.Dashboard)`. On error, log and continue — never block dispatch.
3. Build URL `http://localhost:PORT/?req=<id>&bootstrap=<nonce>`. Print banner.
4. Call `IsHeadless`; if false, `openBrowser(url)` (reusing existing `web.openBrowser`).
5. Continue with `runResume`.

For `--background`, do the same before the fork — banner survives because parent process prints it before exec'ing.

### Edits to `internal/cli/dashboard.go`

Promote `dashboard` from a leaf command to a parent with three subcommands:

- `vxd dashboard` (no sub) — keeps existing behaviour (`--web`, `--all`, `--port`, `--no-open`) for back-compat. The default action is still "launch TUI or web in the foreground". The new pidfile/bootstrap flags are added but optional.
- `vxd dashboard status` — read pidfile + healthz; print `pid 12345 | port 8787 | up 2h13m | http://...` or `not running`.
- `vxd dashboard stop` — SIGTERM the PID, wait up to 5 s, remove pidfile. Idempotent: "not running" if no pidfile.

### New `internal/cli/watch.go`

`vxd watch [req-id]` — compact follow-mode tail. If no `req-id`, defaults to the most recent requirement in the current repo (latest `REQ_SUBMITTED` whose `RepoPath` matches `cwd`). Uses `EventStore.Tail(ctx, state.EventFilter{ReqID: reqID})` if such an API exists, or polls `events.jsonl` since last offset on a 250 ms interval. Renders one line per event using the same formatting `vxd events` already uses, but follows instead of returning.

Stop on Ctrl+C or when the requirement reaches a terminal status (`completed`, `failed`, `archived`). Print `Done.` and exit 0.

### Config additions

In `internal/config/config.go`:

```go
type DashboardConfig struct {
    AutoOpen  bool `yaml:"auto_open"`   // default true
    AutoStart bool `yaml:"auto_start"`  // default true
    Port      int  `yaml:"port"`        // default 8787
}
```

Hung off the top-level `Config` struct as `Dashboard DashboardConfig`. Defaults applied in `loadConfig` if zero.

Operator switches:

- `dashboard.auto_start: false` → `vxd req` never spawns the daemon; nothing changes from current behaviour.
- `dashboard.auto_open: false` → daemon spawns but no browser opens; URL is printed.
- `--no-dashboard` flag on `vxd req` → one-shot disable.

## Data flow

```
vxd req "X"
  → ensureDashboardDaemon
       → read ~/.vxd/dashboard.pid
       → IsAlive?
            yes → GET /internal/bootstrap → fresh nonce → return (port, nonce)
            no  → Spawn(detached): vxd dashboard --web --pidfile=… --bootstrap-file=…
                  → poll GET /healthz until 200 (timeout 3 s, poll 100 ms)
                  → read bootstrap-file → nonce
  → print banner with URL
  → if not headless: openBrowser(url)
  → runResume(reqID)   ← unchanged inline stream
```

## Error handling

| Failure | Behaviour |
|---|---|
| Spawn fails (port in use, exec missing) | Log `[dashboard] auto-spawn failed: <reason>`. Print banner skipped. Dispatch proceeds. |
| Healthz poll times out | Kill child, remove pidfile, log, proceed. |
| Browser open fails | Banner already printed. Log at debug level. |
| Stale pidfile (process gone) | Treat as not-alive, respawn, overwrite pidfile. |
| Pidfile owned by another UID (shared host) | Refuse to overwrite, log warning, skip auto-spawn. |
| `vxd dashboard stop` when not running | Print "not running", exit 0. |
| `vxd watch` with no matching req | Print "no active requirement in this repo; run `vxd req`", exit 1. |
| `dashboard.auto_start: false` | Skip Ensure entirely, no banner. |

The hard rule: **the dashboard daemon never blocks `vxd req`.** Auto-spawn is best-effort; any failure logs and steps aside.

## Security

The web dashboard already requires bearer-token auth via `internal/web/auth.go` (one-time `?bootstrap=<nonce>` URL → `SameSite=Strict HttpOnly` cookie thereafter). The auto-spawn flow:

- Writes the bootstrap nonce to `~/.vxd/dashboard.bootstrap` with mode `0o600`. Only the owner can read.
- Pidfile written with mode `0o600`.
- The `POST /internal/bootstrap` endpoint accepts only loopback (`127.0.0.1` / `::1`) connections — verified by `RemoteAddr` check inside the handler. Even on a shared host this prevents another user from harvesting nonces over the network.
- The existing `WriteHeader(401)` for missing tokens still applies to the dashboard surface itself; only `/internal/bootstrap` and `/healthz` are exempt, and both are bound to loopback.

## Rollout

- Single PR. Behind no flag, defaults to on. Operators who don't want the behaviour set `dashboard.auto_start: false` in `vxd.yaml`.
- No migration needed — daemon is stateless w.r.t. the event log.
- Backwards-compatible: `vxd dashboard` with no subcommand still works exactly as before.

## Open issues

None at spec-write time. The bootstrap-rotation endpoint (`POST /internal/bootstrap`) is the only new server surface and is loopback-gated.
